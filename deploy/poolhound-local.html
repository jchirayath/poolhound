If you script against this API yourself

Switching is PUT /api/<id>/set with a form body value=0 or value=1. It is not GET /api/<id>/set/<value>.

The path form is the trap: it answers 200 and looks like it worked, but carries no value. The daemon parses nothing, compares the circuit against itself, logs not changing state, is same, and never presses. Every retry reaches the same conclusion, so it reads as a broken panel or a daemon bug when the request was simply malformed.

Two things that make a command look broken

The filter pump gates most circuits. With the pump off, the panel refuses aux circuits and the command reads as a failure when it is actually an interlock. Turn the pump on first.

The spa switches off slowly. Valve actuator travel and heater cooldown mean the state does not change immediately, so this page waits before it judges the result.
